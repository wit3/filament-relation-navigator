# アップグレードガイド

このパッケージは[セマンティックバージョニング](https://semver.org/lang/ja/)に従っています。マイナーリリースとパッチリリースでコードが壊れることはありません。このページには、更新時に確認したほうがよい点をまとめています。すべての変更は[変更履歴](/ja/reference/changelog)にあります。

```bash
composer update wit3/filament-relation-navigator
php artisan filament:assets
```

## 1.7 へ

変更は不要です。レコードナビゲーションが有効な場合、**ネストされたリソースでも前後のレコードが表示されます**。同じ親レコードの範囲内で、ネストされたリソースが親のリレーションマネージャーの関連リソース（`$relatedResource`）であれば、そのリレーションマネージャーの並び順に従います。ネストされたリソースで非表示にするには、そのページまたはリソースの `hasRelationNavigatorRecordNavigation()` から `false` を返してください。

## 1.6 へ

変更は不要です。

- 1.6.1 から、パッケージ内部の仕組みには `@internal` が付いています（変更履歴を参照）。`RelationNavigator::optsIn()`、`registerRoutes()` などのヘルパーを呼び出している場合は、[API リファレンス](/ja/reference/api)に載っているものに移行してください。
- 1.6.1 から、対応する Filament の最低バージョンは 4.13 です。

- **メニューのバッジは、ページと一緒ではなく、メニューを開いたときに読み込まれます**。以前の動作に戻すには：`'badges' => true`。1.3 より前に公開したメニュービューや独自のプリセットは、引き続きページと一緒にバッジを受け取ります。
- 「ページとして開く」アクションに新しいオプション（`relation_manager_action`）とフックが追加されました。[ページとして開く](/ja/guide/open-as-page)を参照してください。

## 1.5 へ

変更は不要です。2 つの動作が変わりました。

- レコードナビゲーションが有効な場合、**前後のレコードはキーの順ではなく、ユーザーが来た一覧に従います**（並び順、フィルター、検索、タブ）。キーの順のままにするには：`'record_navigation_follows_list' => false`。
- 「**ページとして開く**」は、リレーションマネージャーが所属するリレーショングループのページよりも、リレーションマネージャー自身のページを優先して開きます。

パッケージのビューを公開している場合は、`menu/partials/list.blade.php` を公開し直してください。タブのバッジが遅延読み込みのリレーションマネージャーは、メニューでも遅延読み込みになりました。

## 1.4 へ

変更は不要です。

- 「**ページとして開く**」リンクは、テーブルの上のリンクではなく、リレーションマネージャーのテーブルヘッダーにあるアクションになりました。どこかで無効にしたい場合は、[ページとして開く](/ja/guide/open-as-page)を参照してください（設定、リソース、リレーションマネージャー）。
- `RelationNavigator::renderRelationManagerLink()` は非推奨になりました。パッケージではもう使っていません。独自のレンダーフックでは引き続き動作しますが、2.0 で削除されます。
- すべてのメニューのオプションをリソースでも設定できるようになりました。[ページ、リソース、設定](/ja/guide/menu-presets#%E3%83%98%E3%82%9A%E3%83%BC%E3%82%B7%E3%82%99%E3%80%81%E3%83%AA%E3%82%BD%E3%83%BC%E3%82%B9%E3%80%81%E8%A8%AD%E5%AE%9A)を参照してください。

## 1.3 へ

::: danger セキュリティ修正
バージョン 1.0.0 から 1.2.1 では、リレーションページでレコードの `view` ポリシーが適用されていませんでした（[GHSA-v3mh-w7qp-37gc](https://github.com/wit3/filament-relation-navigator/security/advisories/GHSA-v3mh-w7qp-37gc)）。レコードにポリシーを使っている場合は、更新してください。
:::

- **デフォルトのメニューが、検索フィールド付きの `github` プリセットになりました。** 設定ファイルを公開している場合は、設定した内容がそのまま使われます。1.2 のメニューのままにするには：

  ```php
  // config/filament-relation-navigator.php
  'menu' => [
      'preset' => 'simple',
      'searchable' => false,
  ],
  ```

- レコードを編集できないユーザーには、メニューに編集ページが表示されなくなりました。
- 新しいオプションには、すべてコード内にデフォルト値があります。1.2 で公開した設定ファイルはそのまま動作します。変更したいときに設定ファイルに追加してください：`relation_manager_link`、`record_navigation`、`redirect_relation_tabs`、`menu.badges` の `'lazy'`。
- パッケージのビューを公開していて `'badges' => 'lazy'` を使いたい場合は、`menu/partials/list.blade.php` を公開し直してください。

## 1.2 へ

- `HasRelationNavigator` が `getRecord()` と `hasRecord()` を宣言するようになりました。レコードのないページは、後になってからではなく、クラスが読み込まれた時点でエラーになります。詳細ページ、編集ページ、`InteractsWithRecord` を使うページは、すでにこれらを持っています。
