# Руководство по обновлению

Пакет следует [семантическому версионированию](https://semver.org/lang/ru/): минорные и патч-версии никогда не ломают ваш код. На этой странице собрано то, на что стоит посмотреть при обновлении. В [списке изменений](/ru/reference/changelog) есть все изменения.

```bash
composer update wit3/filament-relation-navigator
php artisan filament:assets
```

## Переход на 1.7

Ничего менять не нужно. Когда навигация по записям включена, **вложенные ресурсы тоже показывают «предыдущую» и «следующую»**, в пределах той же родительской записи, в порядке relation manager родителя, если вложенный ресурс является его related resource (`$relatedResource`). Чтобы скрыть их на вложенном ресурсе, верните `false` из `hasRelationNavigatorRecordNavigation()` на его страницах или на ресурсе.

## Переход на 1.6

Ничего менять не нужно.

- С 1.6.1 внутренняя часть пакета помечена `@internal` (см. список изменений): если вы вызываете `RelationNavigator::optsIn()`, `registerRoutes()` или похожие вспомогательные методы, перейдите на то, что перечислено в [справочнике API](/ru/reference/api).
- С 1.6.1 минимальная допустимая версия Filament — 4.13.

- **Бейджи меню загружаются при открытии меню**, а не вместе со страницей. Для прежнего поведения: `'badges' => true`. Представления меню, опубликованные до 1.3, и ваши собственные пресеты по-прежнему получают их вместе со страницей.
- У действия «Открыть как страницу» новые опции (`relation_manager_action`) и хуки: см. [Открыть как страницу](/ru/guide/open-as-page).

## Переход на 1.5

Ничего менять не нужно. Изменилось поведение в двух местах:

- **«Предыдущая» и «следующая» следуют списку, из которого вы пришли** (сортировка, фильтры, поиск, вкладка), а не порядку ключей, когда навигация по записям включена. Чтобы оставить порядок ключей: `'record_navigation_follows_list' => false`.
- **«Открыть как страницу»** открывает собственную страницу relation manager раньше, чем страницу группы связей, в которую он тоже входит.

Если вы публиковали представления пакета, опубликуйте `menu/partials/list.blade.php` снова: relation manager с ленивым бейджем вкладки теперь загружают его так же и в меню.

## Переход на 1.4

Ничего менять не нужно.

- Ссылка **«Открыть как страницу»** теперь — действие в шапке таблицы relation manager, а не ссылка над ней. Если где-то её нужно отключить, см. [Открыть как страницу](/ru/guide/open-as-page): конфиг, ресурс или relation manager.
- `RelationNavigator::renderRelationManagerLink()` устарел: пакет его больше не использует. Он ещё работает для вашего собственного render hook и будет удалён в 2.0.
- Любую опцию меню теперь можно задать и на ресурсе: см. [Страница, ресурс или конфиг](/ru/guide/menu-presets#страница-ресурс-или-конфиг).

## Переход на 1.3

::: danger Исправление безопасности
Версии с 1.0.0 по 1.2.1 не применяли политику `view` для записи на страницах связей ([GHSA-v3mh-w7qp-37gc](https://github.com/wit3/filament-relation-navigator/security/advisories/GHSA-v3mh-w7qp-37gc)). Если вы используете политики для записей, обновитесь.
:::

- **Меню по умолчанию теперь — пресет `github` с полем поиска.** Если вы публиковали конфиг, у вас остаются ваши настройки. Чтобы оставить меню версии 1.2:

  ```php
  // config/filament-relation-navigator.php
  'menu' => [
      'preset' => 'simple',
      'searchable' => false,
  ],
  ```

- Меню больше не показывает страницу редактирования пользователям, которые не могут редактировать запись.
- Новые опции, у всех есть значения по умолчанию в коде: конфиг, опубликованный в 1.2, продолжает работать. Добавляйте их в конфиг, когда хотите изменить: `relation_manager_link`, `record_navigation`, `redirect_relation_tabs` и `'lazy'` для `menu.badges`.
- Если вы публиковали представления пакета и хотите `'badges' => 'lazy'`, опубликуйте `menu/partials/list.blade.php` снова.

## Переход на 1.2

- `HasRelationNavigator` теперь объявляет `getRecord()` и `hasRecord()`: страница без записи падает сразу при загрузке класса, а не позже. У страниц просмотра и редактирования и у страниц с `InteractsWithRecord` они уже есть.
