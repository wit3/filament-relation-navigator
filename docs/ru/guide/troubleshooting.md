# Решение проблем

## Меню не показывается

- Страница должна использовать `HasRelationNavigator`. На страницах связей он есть всегда.
- В меню должно быть хотя бы два элемента: сама страница и ещё одна.
- Страница, которая сама строит хлебные крошки, должна возвращать `$this->withRelationNavigator([...])`.
- На экранах шириной меньше 40rem Filament скрывает хлебные крошки: меню переезжает над заголовком (`menu.mobile`).

## Меню выглядит неправильно или стрелка не на месте

Снова опубликуйте таблицу стилей плагина, после каждого обновления:

```bash
php artisan filament:assets
```

## Страница связи отдаёт 404

- У relation manager нет страницы: ресурсу нужен `HasRelationPages` или relation manager нужен `InteractsWithRelationPage`, и он не должен быть исключён.
- Его слаг совпадает с ключом страницы ресурса (`edit`, `view`...): такие слаги пропускаются. Выберите другой через `$relationPageSlug`.
- Если маршруты закешированы, закешируйте их снова после деплоя: `php artisan route:cache`.
- Политика отказывает в доступе к записи «как не найдено» (`Response::denyAsNotFound()`): этот 404 намеренный.

## Страница связи отдаёт 403

Странице связи нужны `canAccess()` страницы просмотра, политика `view` для записи (`update` для страницы редактирования), `canViewForRecord()` relation manager и, если вы его определили, `canAccessRelationPage()` ресурса. Проверьте их в этом порядке.

## Бейджи не показываются

- `menu.badges` равно `false`, их отключает страница или ресурс, или сам relation manager (`hasRelationNavigatorBadge()`).
- По умолчанию они загружаются при открытии меню, со спиннером. Если спиннер не останавливается, посмотрите в консоли браузера, не упал ли запрос Livewire.
- Представления, опубликованные до 1.3, не умеют загружать бейджи позже: они получают их вместе со страницей.

## Сочетание клавиш не работает

- Оно ничего не делает, пока вы печатаете в поле.
- Сочетание глобального поиска панели (`globalSearchKeyBindings()`) никогда не перехватывается: выберите другое через `menu.shortcut`.
- Те же клавиши может занимать расширение браузера или операционная система.

## Нет «Открыть как страницу»

- `relation_manager_link` равно `false`, или действие отключает ресурс или relation manager.
- У relation manager нет своей страницы, или вы уже на ней.
- В таблице с собственным представлением `->header()` нет места для действий в шапке.

## Нет кнопок «предыдущая» и «следующая»

- По умолчанию они выключены: `record_navigation`.
- Они скрываются, когда другой записи нет (на вложенном ресурсе — нет другой записи того же родителя).
- Чтобы они следовали порядку списка, список должен быть открыт в этой сессии, при включённой навигации по записям в конфиге или на ресурсе.

## «A directory that only this user can write»

Хранилище доступно только для чтения, поэтому сгенерированные классы страниц попадают во временный системный каталог, а этот каталог принадлежит другому пользователю. Сделайте `storage/framework/cache` доступным для записи, удалите каталог, указанный в сообщении, или выберите свой в service provider:

```php
GeneratedRelationPages::useCachePath(storage_path('app/relation-pages'));
```

## Всё ещё не работает

Спросите в [GitHub Discussions](https://github.com/wit3/filament-relation-navigator/discussions) или откройте [issue](https://github.com/wit3/filament-relation-navigator/issues) с вашей версией Filament и несколькими строками кода, которые воспроизводят проблему.
